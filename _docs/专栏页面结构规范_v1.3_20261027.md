# 一、这份规范管什么

专栏（K3 / mBox / 软件 …）指的是「单个主题的用户声音看板」。本规范约束它们的**页面结构**，不约束具体数据内容。

| 项 | 说明 |
|---|---|
| 强制力 | 新开专栏必须按本规范的五段骨架搭；已上线专栏按 §九 逐步对齐 |
| 基准实现 | `creality-k3.html`（K3 专栏，2026-10-27 版）—— 有歧义时以它为准 |
| 落地载体 | 文档管「为什么」，`_col_shell.html` 管「不许走形」 |
| 不适用范围 | 资讯日报首页（index.html）、品牌库、切片速查 —— 它们不是专栏，不走五段骨架 |

**核心原则：骨架强制，面板按数据准入。**
照搬面板会让新专栏长出一堆失真的图。规范只强制五段的位置和顺序，每段里画什么，由数据是否够格决定。

## 改哪里，不要改哪里

mBox 和软件两页**不是手写页面，是生成产物**：

```
_col_shell.html   ← 模板（五段骨架 + 全部 CSS + 渲染函数）
      ↓  _build_column.py 注入 __DATA__
creality-mbox.html / software-columns.html   ← 产物，自包含单文件
```

| 动作 | 正确做法 | 错误做法 |
|---|---|---|
| 改版式 / 加面板 | 改 `_col_shell.html`，再跑 `python _build_column.py` | 直接改产物 —— 下次生成即丢失 |
| 改数据 | 改 `_col_items_*.json` 数据源，重跑生成器 | 改产物里的 `COL.items` |
| 改 K3 | K3 不走生成器，直接改 `creality-k3.html` | — |

架构是「源码级共用、产物级自包含」：页面对外仍是零依赖单文件，能直接挂内网；但改版必须回到模板，否则两页会各自漂移。


# 二、五段骨架

页面正文自上而下固定五段，顺序不变，段标题用同一样式（左侧 3px 竖条 + 15px 字）。

| 段 | 名称 | 回答的问题 | 强制 |
|---|---|---|---|
| S1 | 专栏头部 | 这是谁的专栏、多久更新一次 | 强制 |
| S2 | 总体概览 | 现在整体什么状况 | 强制 |
| S3 | 专项分析 | 按这个专栏独有的维度看，问题在哪 | 强制 |
| S4 | 渠道结构 | 声音从哪来、哪里还没覆盖 | 强制 |
| S5 | 明细反馈流 | 具体说了什么 | 强制 |

## S1 专栏头部

| 要件 | 内容 | 示例 |
|---|---|---|
| 图标 + 标题 | 一句能说清对象 | Creality K3 用户反馈专栏 |
| 一句话定义 | 机型特性 + 载体口径 + 地域范围 + 更新频率 | 首款 KliTek 四喷嘴换机机型 · 视频/图文/评价三类载体合并统计 · 国内+海外全渠道 · 每日增量 |
| 更新条 | **数据更新时刻 + 内容截至日期** 双时间 | 数据更新 2026-10-27 11:01 · 内容截至 2026-10-26 |
| 更新历史 | 可展开的增量日志 | 抓取 19 个信源 · 本次新增 7 条 |

双时间是硬要求：只显示内容日期，看不出任务跑没跑；只显示抓取时间，内容长期不动又会被误读成「有更新」。两段并存才可自证。

## S2 总体概览

| 面板 | 口径 | 准入条件 |
|---|---|---|
| KPI 行（5 卡） | 固定 5 槽位，槽位名可按专栏改，但必须是 5 个 | 强制 |
| 情感结构 | 分母 = 计入分析的样本数，五档占比铺满 | 需 `sentiment` 字段覆盖 ≥ 60% |
| 问题点 Top | 只算有效档（泛讨论不进） | 需 `problemPoints` / `problemType` |
| 信源结构 | 按渠道组 / 来源类型 | 强制 |

情感结构、问题点 Top 数据不足时**不渲染该面板**，不放空图。

### 布局：单容器左右并排

S2 的所有面板必须放进**同一个网格容器**，左右并排，不得上下堆叠。

这条是补一个真实事故：v1.0 的实现是两个独立的 `.grid-2` 容器（`ovA` / `ovB`），每个容器只放一个面板 —— 结果每个面板只占半宽、右半片空白，两个容器又竖直堆叠，纵向被拉长一倍。截图看像「上下太挤」，实际是**容器重复**加上**宽度浪费**。

| 规则 | 值 | 理由 |
|---|---|---|
| 容器 | 1 个，所有面板先进字符串再统一落盘 | 两个容器必然各占半宽 |
| 比例（软件类，含矩阵面板） | `minmax(0,.85fr) minmax(0,1.35fr)` | 矩阵 8 列，1:1 会让「多色与耗材」这类行名折行 |
| 比例（其余专栏） | `1fr 1fr` | 纯条形榜对宽度不敏感 |
| 塌陷断点 | ≤ 900px 才变单列 | 原断点 1100 会把 1024 视口误判成窄屏 |

矩阵类面板必须包一层 `overflow-x:auto`，行名加 `white-space:nowrap` —— 并排后容器变窄，宁可横向滑动，不可把行名裁掉。

## S3 专项分析

这一段的唯一作用是回答「按这个专栏自己的逻辑切，哪一块最痛」。所以它是区分专栏的东西，不是 K3 专属的机型特性。

| 专栏 | 主维度 | 辅维度 |
|---|---|---|
| K3 | 机型特性（14 个 topic） | 关注维度分布 |
| 软件 | 用户实现路径六段 S1–S6 | 工具结构（切片/建模/云平台…） |
| mBox | 机型关注点（9 个 topic） | 关注点分布 |

**三条硬规则：**

1. **维度必须显式定义**，写在代码里的 `TOPIC_META` 常量，不是从数据 `group by` 出来。数据里没出现的维度也要出现在列表里。
2. **0 条也要出卡片**，标「待样本」。只显示有数据的维度，会把「没采到」读成「没问题」。标记做成标题行里的小块（名称与数字之间），完整口径写进 `title` 提示与分布面板脚注 —— 见上文「卡片高度必须由内容类型决定」。
3. **自动标注要声明**。关键词规则打的标签，卡片上必须写「规则预标注」，不能冒充人工结论。
4. **跨工具专栏不得把「版本号」当维度**。版本只在单一产品内部可比 —— Creality Print 7.x、OrcaSlicer 2.x、Bambu Studio 1.x、Cura 5.x 的版本号体系相互独立，混进一张「主版本热度」里会被读成同一产品的版本演进，这是错误结论而非弱结论。全行业专栏应改用「工具 × 环节」这类跨工具正交的视角；单一产品专栏（如 K3 的固件版本）不受此限。

## S4 渠道结构

这一段拆两个子件，准入条件不同 —— 这是本规范最容易走形的地方。

| 子件 | 回答 | 准入 | 数据不足时 |
|---|---|---|---|
| 渠道覆盖清单 | 目标渠道里我们覆盖了哪些、缺哪些 | **必显**，0 条也要列出 | 全部标「缺口 / 待接入 / 不可自动」 |
| 渠道占比榜 | 用户声音在各平台的分布 | 有效平台 **≥ 5 个** 才渲染 | 显示「未达门槛，不出占比图」+ 原因 |
| 渠道 × 情感矩阵 | 平台间情感差异 | 需 ≥ 3 平台且有 sentiment | 不渲染 |
| 竞品 / 对标提及 | 被拿来比较的机型 | 有数据才出 | 不渲染 |
| 声量 × 情感趋势 | 按发布日的走势 | 时间跨度 ≥ 14 天 | 不渲染 |

**为什么占比榜要设 5 个平台的门槛：**
2–3 个平台下的百分比会被读成「用户分布」，实际只是采集能力的倒影。画出 90% / 10% 的饼不是洞察，是噪音。而覆盖清单在任何数据量下都成立 —— 它回答的是「还差哪些渠道」，源少的时候缺口反而更刺眼。

**2026-10-27 起**：软件专栏已接入 6 个信源（官方论坛 / GitHub / Reddit / B站 / YouTube / 什么值得买），占比榜首次达到门槛并开始渲染；mBox 为 5 个（B站 / YouTube / 3druck / Reddit / 什么值得买），仍在门槛边缘，其中 Reddit 实际 0 条。

**「0 条」和「未接入」必须分开显示**：`已接入 · 0 条`（活已干完，确实没内容）与 `待接入`（还要排期）在管理上是两件事，用同一个标签会误导。

## S5 明细反馈流

| 要件 | 要求 |
|---|---|
| 筛选层 | 至少两层：基础筛选（下拉）+ 深层筛选（问题点/维度/关注点） |
| **渠道筛选器** | 按钮组，放在筛选栏第一位，每个按钮带条数 |
| 已选条件 | chips 展示，每项可单独删除，另有「清空全部」 |
| 计数行 | 当前区间 + 总样本数 + 数据更新时间 + 时间区间口径（按发布日/采集日） |
| 卡片网格 | 四列（见 §六） |
| 分页器 | 上一页 / **页码下拉直达** / 共 N 页 / 下一页 |

页码下拉是硬要求：558 条数据是 28 页，只有「上一页/下一页」等于没法用。

### 渠道筛选器：按钮组，不是下拉

明细流的第一个筛选器必须是**具体渠道**（YouTube / Reddit / B站 / 什么值得买 / 官方论坛…），用按钮组而不是下拉。

理由：下拉要先展开才知道有哪些渠道、各多少条，读者是在「不知道自己能筛什么」的状态下操作。按钮组把「有哪些渠道、各自多少条」直接摊在眼前，一次点击进到该渠道，再点一次取消。

| 规则 | 值 |
|---|---|
| 形态 | `全部 N` + 各渠道 `渠道名 N`，选中态高亮 |
| 排序 | 按条数降序，不按字母 |
| 长尾折叠 | 渠道 ≤ 8 个全显示；> 8 个只显示「≥5 条」的前 8 个，其余收进「其他渠道 N 个」下拉 |
| 命名归一 | `B 站` / `B站` 等空格差异必须先归一，否则同一个渠道会裂成两个按钮 |

长尾折叠的门槛来自 K3 实测：14 个平台里 4 个占 96%（YouTube 332 / B站 44 / Reddit 25 / 什么值得买 19），其余 10 个各只有 1–2 条。全部铺开会把筛选栏撑成两屏，而筛出来只有一条内容。

### 三个筛选维度不得混用

明细流里同时存在三个容易混淆的维度，必须各自独立、标签写清楚：

| 维度 | 字段 | 取值示例 | 回答的问题 |
|---|---|---|---|
| 渠道 | `platform` | YouTube / Reddit / B站 / 官方论坛 | 「这条来自哪个渠道」 |
| 市场 | `channel` | 国内 / 海外 | 「这是哪个市场的声音」 |
| 信源类型 | `sourceType` | 用户 / 媒体 / 官方 / 论坛 / 导购 / GitHub | 「这是谁说的、什么性质」 |

把「渠道」塞进「信源类型」是最常见的错法：`sourceType` 是性质分类，Reddit 和 YouTube 都属「用户」，一旦合并就再也筛不出单渠道。

## 纵向节奏与卡片行高

结构对了、间距不对，读起来还是「挤」。纵向节奏只有两个值，不允许第三种：

| 层级 | 值 | 用在哪 | 实现 |
|---|---|---|---|
| 区块内 | 12px | 段标题 → 首个元素、卡片组 → 后续面板、面板 → 面板 | 元素自身 `margin-top` 或 `.mt12` 工具类 |
| 区块间 | 24px | 上一段最后一个元素 → 下一段 `sec-title` | `sec-title` 的 `margin-top` |
| 卡片间 | 10px | 同一 `topic-grid` 内的行列间距 | `gap` |

三条硬约束：

1. **面板堆叠不许贴住**。任何「面板 → 面板」的堆叠，前者不能是最后一个子元素且无 `margin-bottom` —— 必须由后者给 `margin-top:12px`。v1.2 的模板里 S3 卡片组 → 关注点分布、S4 覆盖清单 → 占比榜两处漏了，实测 `gap=0`，卡片边缘直接压在面板边框上。
2. **卡片高度必须由内容类型决定，不被状态标记改变**。专项分析卡恒为「标题行 + 描述行」两行；`待样本` 这类 0 条标记放在**标题行**（名称与数字之间），不自占一行。否则同一行里只要有一张 0 条卡，整行被撑高 25px，与上一行不齐，看上去像网格坏了。
3. **名称列不换行、超长省略**。标题行用 `名称(flex:1, ellipsis) + 标记 + 数字`，描述固定单行 —— 行高才是确定的。

校验方式（不用肉眼）：无头浏览器量 `.main` 直接子元素的两两间距，应只有 12 / 24 两个值；再量 `#topicGrid` 每张卡的 `height`，同组内应全部相等。

```js
// 量间距：把结果写进 title，chrome --dump-dom 取回

```

# 三、面板准入速查

新专栏开工前对照这张表决定画什么，不画什么。

| 面板 | 需要的字段 | 阈值 | 不满足时 |
|---|---|---|---|
| KPI 五卡 | 任意 | 强制 | — |
| 情感结构 | `sentiment` | 覆盖率 ≥ 60% | 隐藏 |
| 问题点 Top | `problemPoints` 或 `problemType` | ≥ 10 条有效档 | 显示空态说明 |
| 信源结构 | `channel` | 强制 | — |
| 专项分析卡片 | `topics` 或专栏主维度字段 | 维度显式定义 | 0 条标「待样本」 |
| 渠道覆盖清单 | `platform` + 目标渠道表 | 强制 | 全标缺口 |
| 渠道占比榜 | `platform` | 有效平台 ≥ 5 | 显示未达门槛 |
| 渠道 × 情感矩阵 | `platform` + `sentiment` | ≥ 3 平台 | 隐藏 |
| 趋势图 | `date` / `publishedAt` | 跨度 ≥ 14 天 | 隐藏 |
| 明细卡片 | `title` + `originalText` + `url` | 强制 | — |

# 四、数据契约

结构是字段的函数。字段缺了，再像 K3 的壳也填不进内容。

| 字段 | 必填 | 用途 | 缺失后果 |
|---|---|---|---|
| `uid` | 是 | 卡片锚点、去重 | 条目无法定位 |
| `date` | 是 | 采集日、时间筛选、趋势 | 时间轴失效 |
| `publishedAt` | 建议 | 发布日（与采集日分开口径） | 只能按采集日看 |
| `platform` | 是 | 渠道清单、占比榜 | S4 无法渲染 |
| `site` | 建议 | 同站多平台合并 | 站点集中度失真 |
| `channel` | 是 | 渠道组、信源结构 | S2 缺一块 |
| `country` | 建议 | 地域筛选 | — |
| `language` | 是 | 原文语种、译文提示 | 译语种标错 |
| `title` / `titleCn` | 是 | 卡片标题 | 卡片无题 |
| `originalText` | 是 | 原文段 / 摘要来源 | 只剩标题 |
| `textCn` | 非中文必填 | 机翻段 | 中文读者读不了 |
| `sourceType` | 是 | 载体结构、标签 | 无法区分官方/媒体/用户 |
| `contentKind` | K3 类必填 | 视频 / 图文 / 评价 | 无法标载体、评论无父级回链 |
| `sentiment` | 情感结构必填 | 情感面板 | 该面板不可渲染 |
| `problemPoints` | 问题结构必填 | 问题点 Top | 该面板空态 |
| `topics` | 专项分析必填 | 维度卡片 | S3 不可渲染 |
| `url` | 是 | 原文回溯 | 无法查证 |
| `grade` | 建议 | 有效 / 泛讨论分档 | 分析口径不分档 |
| `heat` | 建议 | 卡片脚注热度 | — |
| `countInVolume` | 多源专栏必填 | 是否计入「总声量」 | 缺陷单 / 导购会把声量口径撑大 |
| `price` | 导购类必填 | 到手价，卡片徽章 | 导购条目看不出关键信息 |
| `author` | 建议 | 官方/用户的判据、可追溯 | 只能靠 sourceType 粗判 |

**`countInVolume=false` 的两类内容，处理必须一致**：GitHub 缺陷单（可复现缺陷，非用户声量）、什么值得买导购（价格信号，非反馈）。两者都进明细、都单列条数、都不进 KPI 声量、都不进问题结构（`problemType` 不参与统计）。这是站内已有先例，新专栏照抄。

# 五、信源准入与采集约束

结构可以复制，**数据复制不了**。一个专栏宣称的覆盖面，永远不能超过它实际采到的信源。
2026-10-27 把软件专栏从「自家软件反馈」改为「全行业软件舆情」时，所有踩过的坑都在这。

## 一个源能不能接，先看三件事

| 判据 | 为什么 | 反例 |
|---|---|---|
| 有没有可用的抓取入口 | 前端 SPA / JS 挑战页无法自动抓 | 什么值得买站内搜索返回 202 挑战页，只有分类页可读 |
| 内容性质对不对得上 | 导购站的 3D 打印内容全是整机好价，没有软件讨论 | 什么值得买 9 条 3D 打印机分类，软件相关命中 **0 条** |
| 命中率够不够 | 主版综合区噪声 98% 时，靠关键词过滤几乎捞不到东西 | r/3Dprinting 标题级软件命中约 2% |

## 各源实测约束（2026-10-27）

| 源 | 入口 | 硬约束 | 在软件专栏的角色 |
|---|---|---|---|
| Reddit | `r/{sub}/new.rss` | 匿名配额极小，连发 3 次即 429（`x-ratelimit-remaining: 0`）。必须串行、间隔 ≥7s，429 后退避 20s 起 | 海外软件问题主战场，取 `r/OrcaSlicer`（专版）+ `r/BambuLab`、`r/3Dprinting`（综合版过滤） |
| B站 | 搜索 API（公共模块 `_bili_search.py`） | 需 warmup 取 cookie；`-352` 风控要退避 | 国内创作者实测 |
| YouTube | Data API v3 `search` | 需 apiKey（`_k3_creds.json`）；配额 10000/天，每次 search 100 单位 | 海外视频评测与教程 |
| 什么值得买 | `fenlei/3ddayinji/` 分类页 | 站内搜索不可用；**分页无效**（`/p2/` 与 `/p1/` 交集 8/9，实为 SPA），只能拿首屏 9 条 | 只作「周边消费信号」，`countInVolume=false` |

## 词义混叠是最贵的坑

同一个词在不同平台指向完全不同的东西，闸门写不严，专栏一眼就假：

| 词 | 在 3D 打印语境 | 实际被撞到的东西 |
|---|---|---|
| Orca | OrcaSlicer 切片器 | B站/Reddit 上大量指 AI 编程工具 Orca ADE（"我用过最好的 Agent IDE：Orca"） |
| 切片 | 模型切片 | 直播切片、视频剪辑（"DeepSeek 批量剪辑直播切片教程"） |
| 3D | 3D 打印 | 手机膜（"IQOO16 3DAR 膜测试"） |
| infill / support | 切片参数 | 作品展示帖里的顺带描述（"Made a working desk fan"） |

**处置原则：把歧义挡在检索阶段，不要指望闸门兜底。**
检索词写全称（`Orca Slicer`，不写 `Orca`），闸门再做二次排除。

## 闸门三级，不要一律放宽

| 级别 | 适用 | 判定 |
|---|---|---|
| 标题级 | 所有源 | 标题命中「软件行为词」（slicer/settings/报错/参数/版本号形式 2.4.2…）即收 |
| 正文级 | 专版（r/OrcaSlicer） | 标题不中时看正文前 600 字，**且必须点名具体工具**（OrcaSlicer / Bambu Studio / Cura / gcode / 3mf…） |
| 不放宽 | 综合版（r/3Dprinting） | 正文命中同样要求点名工具，否则作品帖会靠 `infill` 混进来 |

实测差别：软件专栏外部源 353 条 → 收严后 234 条，删掉的 119 条几乎全是模型展示与歧义噪声。**宁可少收，不可混收** —— 一条「Halloween bookmark」出现在软件专栏首屏，整页可信度就没了。

## 采集失败不等于没有声量

一个源挂了，页面要老实说「此处没采到」，不能填 0 条当成「没有声音」。
`_reddit_search` 等模块的设计原则：429 只记 `errors`、不抛异常、不阻断其他源；页面渠道清单用 `已接入 · 0 条` 区分「采过但没有」和「还没接」。

# 六、文案口径

| 场景 | 写法 |
|---|---|
| 0 条维度 | 标题行标「待样本」小块；`title` 提示写「空白 ≠ 无问题」 |
| 0 条渠道 | 「缺口 / 待接入 / 不可自动」，不写「暂无」 |
| 自动标注 | 明确写「规则预标注」或「自动标注」，不写「分析得出」 |
| 归并帖 | 注明「N 条为归并帖，不等于 N 个独立来源」 |
| 口径变化 | 注明生效日期与原因，例「10-19 起含评价类，柱高与之前不可直接比」 |
| 机翻 | 固定标「机器翻译」，不冒充人工译文 |

空态文案必须说清「是没数据，还是没有这个问题」。这两件事在页面上长得一样，结论却相反。

# 七、四列卡片

## 断点

卡片网格用 `repeat(auto-fill, minmax(340px, 1fr))`，内容区宽度 = 视口 − 256px（侧栏 200 + 内边距 56）。

| 视口 | 内容区 | 列数 |
|---|---|---|
| ≥ 1652px（1920 基准） | ≥ 1396px | **4 列** |
| 1200–1651px（1440 基准） | 944–1395px | 3 列 |
| < 1200px | < 944px | 2 列 |

「一屏 4 卡」是 1920 基准下的形态，1440 笔记本上是 3 列。这是栅格的自然结果，不做强制。

## 卡片要件（自上而下）

| 区 | 内容 |
|---|---|
| 头行 | 载体标签 · 审核档 · 情感 · 渠道 · 来源类型 · 日期 · 平台 · 原文链接 |
| 标题 | 中文标题，最多 2 行，悬浮显示全文 |
| 原标题 | 有中文标题时补一行原文标题，2 行截断 |
| **摘要** | 4 行截断，见下 |
| 展开 | 「展开全文 ▾」，就地展开原文 + 机翻，不跳走 |
| 折叠区 | 原文段（标注语种）+ 译文段（标「机翻」） |
| 脚注 | 热度 · 原文跳转 |

## 摘要规则

卡片正文**一律给摘要，不铺原文**。四列布局下，全文会把卡片高度拉开，整行按最高卡片留白，比单列还难看。

摘要取值优先级：

1. 人工 / 批量生成的 `summaryCn`
2. 译文首句（≥ 40 字才用，否则取全段）
3. 原文首句（先剥掉与标题重复的部分）
4. 标题本身

**摘要与标题重复时不渲染摘要行。** 宁可少一行，也不要卡片里出现两句一样的话。

原文长度不到摘要 1.3 倍时不显示「展开全文」按钮 —— 没有更多可看的内容。

## 本次顺带修掉的一个数据缺陷

重新生成页面时发现：`track_delta()` 返回的 `delta` 是「本次运行相对快照的新增 uid 数」。不重新采集、只重跑生成器时，所有 uid 都在快照里，`delta` 必然为 0，于是页面的「今日新增」被真实值（mBox 7 条 / 软件 1 条）覆盖成 0，更新历史也一并改写成「本次新增 0 条」。

修法两条：

1. `today` 从「脚本运行日」改为 `fetchedAt` 的日期 —— 跨天重跑不再触发归零分支；
2. 快照里记录 `fetchedAt` 与 `delta`，同一批数据重跑时直接沿用，不改写。

页面上的「今日新增」描述的是 `fetchedAt` 那次抓取的结果，不是脚本运行的结果。这个口径要守住，否则每次改版都会把当天的真实新增数抹掉。
